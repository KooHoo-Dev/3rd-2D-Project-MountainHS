# 작업 전 확인 체크리스트

작업을 시작하기 전에 반드시 아래 항목을 확인한다.

## 수정 범위 확인

- [ ] 사용자가 수정 가능 파일을 명시했는가?
- [ ] 수정하려는 파일이 수정 가능 파일 목록에 포함되어 있는가?
- [ ] 새 파일 생성이 명시적으로 허용되었는가?
- [ ] 새 클래스 생성이 명시적으로 허용되었는가?
- [ ] public 메소드/프로퍼티 시그니처 변경이 명시적으로 허용되었는가?
- [ ] SerializeField 이름 변경이 명시적으로 허용되었는가?

## 금지 사항 확인

- [ ] 요청과 직접 관련 없는 리팩토링을 하지 않는가?
- [ ] 기존 구조를 크게 바꾸지 않는가?
- [ ] 기능 전체를 새로 설계하지 않는가?
- [ ] 새 매니저, 새 시스템, 새 아키텍처를 임의로 만들지 않는가?
- [ ] Inspector 연결을 깨뜨릴 가능성이 없는가?
- [ ] public API를 사용하는 다른 코드에 영향을 주지 않는가?

## 코드 스타일 확인

- [ ] 기존 코드 스타일을 유지하는가?
- [ ] C# 기본 문법 위주로 작성하는가?
- [ ] LINQ를 사용하지 않는가?
- [ ] 람다식을 사용하지 않는가?
- [ ] 델리게이트/이벤트 고급 문법을 사용하지 않는가?
- [ ] 초보자가 읽고 이해할 수 있는 코드인가?
- [ ] 불필요한 추상화가 없는가?

## 구현 범위 확인

- [ ] 요청받은 기능 하나만 처리하는가?
- [ ] 최소 변경으로 해결하는가?
- [ ] 다른 기능의 동작을 바꾸지 않는가?
- [ ] 애매한 부분을 임의로 확장하지 않는가?
- [ ] 범위를 넘는 내용은 TODO 주석 또는 질문으로 처리하는가?

## 중단 조건

아래 상황이 발생하면 즉시 작업을 멈추고 사용자에게 질문한다.

- [ ] 수정 허용 파일 외의 파일을 수정해야 할 것 같을 때
- [ ] 새 파일 생성이 필요할 때
- [ ] 새 클래스 생성이 필요할 때
- [ ] public 메소드/프로퍼티 변경이 필요할 때
- [ ] SerializeField 이름 변경이 필요할 때
- [ ] 기존 구조를 크게 바꿔야 해결될 것 같을 때
- [ ] 요청 범위가 불명확할 때
